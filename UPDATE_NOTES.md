# 🆕 Версия 2.1.1 (сентябрь 2026)

Патч-релиз: исправления багов и мелкие улучшения поверх 2.1.

## 🐛 Исправленные баги

1. **Клавиатура на разбитых сообщениях** — если ответ с inline-кнопками был
   длиннее 4000 символов и разбивался на части, клавиатура продублировалась
   на каждой части. Теперь кнопки прикрепляются только к последней части.
2. **Дубли имён устройств** — при совпадении `friendly_name` алиас молча
   указывал на последнее устройство, и `/off <имя>` мог выключить не то.
   Неоднозначные имена теперь исключены из точного поиска (остаётся
   подстрочный с выбором кнопками); в лог пишется предупреждение.
3. **Восстановление таймеров** — повреждённая запись в `data/timers.json`
   (`KeyError` на `eid`/`minutes`) прерывала восстановление всех остальных
   таймеров. Битые записи теперь пропускаются с записью в лог.
4. **`/scene` без ответа пользователю** — ловился только `HAError`;
   сетевые ошибки httpx улетали молча. Теперь ловятся все ошибки.
5. **`/toggle` недоступного устройства** — при состоянии `unavailable`
   устройству отправлялся `turn_off`. Теперь бот сообщает, что устройство
   недоступно (также в inline-карточке).
6. **Неверный `HA_TIMEOUT`** — нечисловое значение роняло бота на старте
   с traceback. Теперь берётся 15 с с предупреждением в лог.
7. **Локализация `/timers`** — в кнопках таймеров подпись «мин» была
   захардкожена по-русски; теперь переводится (ru/en).

## ✨ Улучшения

8. **Персистентность таймеров** — `timers.json` сохраняется при каждом
   создании/отмене/срабатывании таймера, а не только при штатном shutdown.
   Таймеры переживают kill -9, OOM и перезагрузку хоста.
9. **Rate limit на `/notify`** — не более 20 запросов в минуту
   (защита от спама через приёмник уведомлений).
10. **«Message is not modified»** — повторное нажатие кнопки с тем же
    результатом больше не пишет warning в лог.
11. **Признак обрезки поиска** — если найдено больше устройств, чем
    показывает список кнопок (20), в сообщении видно, сколько ещё.
12. **Комнаты из атрибутов** — пустой атрибут комнаты (`room_name: []`)
    больше не отменяет проверку остальных атрибутов.
13. **Удалена мёртвая ветка** в `_send_or_edit`/`_show_status_list`
    (ветка `>4096` была недостижима и содержала скрытый `AttributeError`).
14. **Скрипты**: `stop.sh` ищет процесс точнее (`venv/bin/python bot.py`,
    не убьёт чужой python); из fallback-установки в `install.sh` удалён
    неиспользуемый `pydantic`; `Dockerfile` — убран фиксированный
    `EXPOSE 8099` (порт задаётся через `NOTIFY_PORT`).

## ⬆️ Обновление с версии 2.1

```bash
cd /opt/ha-telegram-bot
git pull
sudo systemctl restart ha-telegram-bot
```

Настройки и данные совместимы, менять `.env` не нужно.

# 🆕 Версия 2.1 (сентябрь 2026)

Обновление с исправлениями и улучшениями поверх 2.0.

## 🐛 Исправленные баги

1. **Healthcheck Docker** — старая проверка (`sys.exit(0)`) всегда возвращала
   успех, даже если процесс завис. Теперь проверяется PID 1 (`os.kill(1, 0)`).
2. **Приёмник уведомлений** — занятый или недоступный `NOTIFY_PORT` больше не
   роняет бота целиком: приёмник отключается с ошибкой в логе, а управление
   устройствами продолжает работать.
3. **Payload уведомлений** — вариант `{"text": "{{ message }}"}` ломался на
   кавычках и переводах строк в тексте. Рекомендуется
   `payload: '{"text": {{ message | tojson }}}'`.
4. **Обрезка длинных сообщений** — отдельная строка длиннее лимита теперь
   жёстко обрезается, при битом HTML срабатывает fallback на plain text.
5. **Поиск в командах** — `/on`, `/off`, `/toggle`, `/scene`, `/set` раньше
   понимали только точный алиас; теперь при неточном вводе бот предлагает
   список совпадений кнопками.
6. **Дубли имён устройств** — при одинаковых `friendly_name` алиас молча
   перезаписывался последним устройством; теперь пишется предупреждение в лог.
7. **Рассылка уведомлений** — fallback на `ALLOWED_USER_IDS` при отсутствии
   известных чатов (в группах `user_id != chat_id`) помечается предупреждением.
8. **Зависимости** — удалён неиспользуемый `pydantic`; для всех пакетов
   добавлены верхние границы версий (`>=x,<y`), чтобы мажорные обновления
   не ломали бота.

## ✨ Новые функции

9. **`/timers`** — список активных таймеров пользователя (время до срабатывания)
   с inline-кнопками отмены.
10. **Пресеты яркости** — в карточке света добавлены кнопки 25/50/75/100%.
11. **`REFRESH_INTERVAL`** — интервал обновления реестра устройств задаётся
    через `.env` (по умолчанию 60 с, минимум 15).

## 🔧 Улучшения

12. Валидация диапазона температуры для `/set` (4–40°): понятное сообщение
    вместо ошибки от HA.
13. Некорректное значение `REFRESH_INTERVAL` в `.env` не роняет бота —
    берётся значение по умолчанию (60).
14. При старте в лог печатаются версия бота и интервал обновления реестра.

## ⬆️ Обновление с версии 2.0

```bash
cd /opt/ha-telegram-bot
git pull
sudo systemctl stop ha-telegram-bot
source venv/bin/activate
pip install --upgrade -r requirements.txt
deactivate
sudo systemctl start ha-telegram-bot
```

Новые настройки имеют разумные значения по умолчанию — менять `.env` не
обязательно. Для серверов с малым объёмом RAM добавьте `REFRESH_INTERVAL=300`.

## ✅ Проверка после обновления

1. `sudo systemctl status ha-telegram-bot` — служба активна
2. В логе при старте: `HA Telegram Bot v2.1, интервал обновления реестра: 60 с`
3. В Telegram: `/timers` → «Активных таймеров нет.»
4. Уведомление с кавычками:
   `curl -X POST -H "Authorization: Bearer <NOTIFY_TOKEN>" \
    -H "Content-Type: application/json" \
    -d '{"text":"тест \"кавычки\"\nи перенос"}' http://localhost:8099/notify`

# 📌 Версия 2.0

Что нового в версии 2.0 по сравнению с 1.0: исправления багов, новые функции,
новые скрипты и полностью обновлённая документация.

## 🐛 Исправленные баги

1. **Команда `/set` реализована** — раньше была заявлена в `/help`, но не существовала.
   Теперь работает: `/set свет 50` → яркость 50% (через корректный сервис
   `light.turn_on` с `brightness` 0–255, а не несуществующий `light.set_brightness`),
   `/set термостат 22` → `climate.set_temperature`. Значения `>100` для света
   трактуются как сырое 0–255.
2. **Таймеры** — ключ изменён с пользователя на пару `(пользователь + устройство)`:
   можно несколько таймеров одновременно, повторный запуск для того же устройства
   отменяет старый с уведомлением. Добавлена валидация диапазона 1–1440 мин.
3. **Комнаты** — настоящие area из Home Assistant через
   `area_registry` / `device_registry` / `entity_registry` (раньше искались
   только несуществующие по умолчанию атрибуты). Fallback на атрибуты
   `room_name`/`area`/`area_name`/`location` сохранён, список атрибутов унифицирован.
4. **Callback-data** — вместо обрезания до 64 байт введён маппинг коротких токенов:
   длинные `entity_id` и имена комнат больше не ломают inline-кнопки.
   Устаревшая кнопка показывает понятное сообщение.
5. **HTML** — обрезка списков по границам строк (теги не рвутся), fallback на
   plain text при ошибке парсинга, сообщения длиннее 4096 отправляются новым
   сообщением вместо падения.
6. **Текстовый ввод** — больше не выключает устройство по умолчанию. Совпадение
   показывает карточку: статус + кнопки Вкл/Выкл/Переключить.
7. **`/state` без аргументов** — показывает живые данные из `/api/states`,
   а не устаревший на 60 секунд кеш.
8. `/scene` проверяет, что найденная сущность действительно `scene.*`.

## ✨ Новые функции

9. **Несколько пользователей** — `ALLOWED_USER_IDS=111,222,333` (через запятую).
   Старый `ALLOWED_USER_ID` продолжает работать. Пустой список = предупреждение
   в логе «доступ разрешён всем».
10. **Уведомления из HA → Telegram** — встроенный HTTP-приёмник (aiohttp):
    `NOTIFY_PORT`, `NOTIFY_HOST`, `NOTIFY_TOKEN`. Home Assistant шлёт сообщения
    через `rest_command`. Поддержка `parse_mode` и `chat_ids`.
11. **Поиск устройств** — ввод части имени показывает список совпадений
    (до 20, точное совпадение открывается сразу).
12. **`/alloff`** — выключение всех `light`/`switch`/`fan`/`cover` с подтверждением
    и отчётом о количестве.
13. **Таймеры переживают перезапуск** — сохраняются в `data/timers.json` при
    штатной остановке, восстанавливаются с оставшимся временем при старте.
14. **Логирование запросов** — каждое обращение фиксируется:
    `Запрос user=123456789: /on свет`.
15. Поддержка `HA_TIMEOUT` и `DATA_DIR` через переменные окружения.
16. `/help` обновлён (все команды + подсказка про поиск).

```env
# Опциональные

NOTIFY_PORT=0                            # порт приёмника уведомлений (0 = выкл)

```

## 🚨 Уведомления из Home Assistant

1. В `configuration.yaml` HA:

```yaml
rest_command:
  telegram_notify:
    url: "http://<IP_сервера_с_ботом>:8099/notify"
    method: POST
    headers:
      Authorization: "Bearer <NOTIFY_TOKEN_из_.env>"
    content_type: application/json
    # tojson экранирует кавычки и переводы строк в тексте сообщения
    payload: '{"text": {{ message | tojson }}}'
```

2. В автоматизациях:

```yaml
- service: rest_command.telegram_notify
  data:
    message: "🚨 Датчик дыма в гараже сработал!"
```

Опционально в payload: `"parse_mode": "HTML"`, `"chat_ids": [123456789]`.

## ⬆️ Обновление с версии 1.0

```bash
cd /opt/ha-telegram-bot
git pull
sudo systemctl stop ha-telegram-bot
source venv/bin/activate
pip install --upgrade -r requirements.txt   # подтянется aiohttp
deactivate
sudo systemctl start ha-telegram-bot
```

После обновления:

- перенесите `user_langs.json` из корня проекта в `data/` (если хотите
  сохранить языки пользователей);
- добавьте в `.env` `ALLOWED_USER_IDS` (формат с ID через запятую);
- активные таймеры на момент обновления будут потеряны (создадутся заново
  при следующих запросах);
- inline-кнопки в старых сообщениях перестанут работать — отправьте `/menu`.

## ✅ Проверка после обновления

1. `sudo systemctl status ha-telegram-bot` — служба активна
2. `sudo journalctl -u ha-telegram-bot -n 30` — в логе `Загружено устройств: N`
3. В Telegram: `/status` → «Home Assistant: онлайн»
4. `/set свет 50` → подтверждение установки значения
5. Уведомление: `curl -X POST -H "Authorization: Bearer <NOTIFY_TOKEN>" \
   -H "Content-Type: application/json" \
   -d '{"text":"test"}' http://localhost:8099/notify`
